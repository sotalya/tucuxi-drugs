=======================
NONMEM files user guide
=======================

The NONMEM files used for cross-validation of Tucuxi need to respect some conventions, as the python scripts will generate some data files and also retrieve data from the NONMEM runs.

This part of the documentation summarizes some hints for writing NONMEM files, and emphysizes the mandatory things required by the python scripts.

There are four different runs currently implemented:

- A priori prediction
- A priori percentiles
- A posteriori prediction
- A posteriori prediction at time of samples

Each type of calculation requires a specific NONMEM file. For a defined drug model, some parts will be identical in all files, and some are specific to a run. The name convention is the following:


- A priori prediction : <drugModelId>.apriori
- A priori percentiles : <drugModelId>.apriori.perc
- A posteriori prediction : <drugModelId>.aposteriori
- A posteriori prediction at time of samples : <drugModelId>.aposteriori.sample

We present here a file for a priori prediction of Imatinib, and then we will explain the different parts.

So, Imatinib a posteriori predictions can be done with the following file:
::

    $SIZES LIM6=15000 NO=15000

    $PROBLEM IMATINIB Model Predictions Etude PK-PD GIST. A posteriori prediction.

    $INPUT ID TIME EVID AMT CMT SS II DV MDV bodyweight gist sex age

    $DATA data.csv IGNORE=@

    $SUB ADVAN2 TRANS2

    $PK
    MEANBW=70;
    FBW=(bodyweight-MEANBW)/MEANBW;

    MEANAG=50;
    FAGE=(age-MEANAG)/MEANAG;

    IF (gist.EQ.1) PATH=1;
    IF (gist.EQ.0) PATH=0;

    TVCL = THETA(1)+THETA(5)*FBW+THETA(6)*sex-THETA(6)*(1-sex)+THETA(7)*FAGE + THETA(8)*PATH-THETA(8)*(1-PATH);

    CL=TVCL * (1 + ETA(1))
    TVV=THETA(2)+THETA(11)*sex-THETA(11)*(1-sex)
    V=TVV * (1 + ETA(2))
    KA=THETA(3)
    KEL=CL/V
    S2=V/1000

    $THETA
    14.3 FIX ; CL
    347 FIX; V
    0.609 FIX; Ka
    1; F
    5.42 FIX
    1.49 FIX
    -5.81 FIX
    -0.806 FIX
    70 FIX
    50 FIX
    46.2 FIX

    $ERROR
    IPRE = -5 ; arbitrary value; to prevent from run stop due to log domain error
    IF (F.GT.0) IPRE = LOG(F) ; note: in FORTRAN, LOG() means natural logarithm, not decimal!
    Y = IPRE + EPS(1)
    IPRED=F

    $OMEGA STANDARD CORRELATION BLOCK(2) FIX
    0.356; IIV CL
    0.798 0.629; IIV V

    $SIGMA 0.3138 STANDARD FIX

    $EST METHOD=1 INTER MAXEVAL=0 NOABORT NSIG=3 PRINT=1 POSTHOC
    PRINT=1
    $TABLE UNCONDITIONAL ID EVID TIME DV IPRED Y
    NOPRINT ONEHEADER FILE=aposteriori.out.dat



Let's explain the various sections.

First, this next line is specific for percentiles, and actually modifies some internal NONMEM buffer sizes to cope with all the data that could be generated. By default, a NONMEM installation defines these sizes, and it is often too small.

::

    $SIZES LIM6=15000 NO=15000

Here, the problem statement starts with $PROBLEM followed by some description:

::

    $PROBLEM IMATINIB Model Predictions Etude PK-PD GIST. A posteriori prediction.


The next line defines the structure of the data fed to NONMEM. It describes the name of the columns in the data.csv file. In this example, we have 4 covariates, corresponding to the last 4 columns:

::

    $INPUT ID TIME EVID AMT CMT SS II DV MDV bodyweight gist sex age

And then, we indicate that the input data are in data.csv. This file will be generated by the python scripts.

::

    $DATA data.csv IGNORE=@

Then, we define the PK model to be used. The available models are described in NONMEM doc file vi.pdf, page 70. Some info is also available in v.pdf, page 68. Actually the full details are in file viii.pdf, around page 200. Finally, the HTML documentation seems easier, as there is one file per model. For instance, there is advan2.htm.

So, here ADVAN2 corresponds to 1 compartment extravascular, and TRANS2 to the use of CL and V instead of micro constants.

::

    $SUB ADVAN2 TRANS2

We continue with the PK model parameters. In this section we write the equations allowing to calculate the PK parameters based on the covariates. It also embeds the variability of the parameters. The influence of covariates are described by means of THETA() values that are declared in the next section.

For instance, TVCL is the a priori clearance, and the final clearance, CL, is calculated with TVCL and its variability.

::

    $PK
    MEANBW = 70;
    FBW = (bodyweight - MEANBW) / MEANBW;

    MEANAG = 50;
    FAGE   = (age - MEANAG) / MEANAG;

    IF (gist.EQ.1) PATH=1;
    IF (gist.EQ.0) PATH=0;

    TVCL = THETA(1) + THETA(5) * FBW + THETA(6) * sex - THETA(6) * (1 - sex) + THETA(7) * FAGE + THETA(8) * PATH - THETA(8) * (1 - PATH);

    CL  = TVCL * EXP(ETA(1))
    TVV = THETA(2) + THETA(11) * sex - THETA(11) * (1 - sex)
    V   = TVV * EXP(ETA(2))
    KA  = THETA(3)
    KEL = CL/V
    S2  = V/1000

The inter-individual variability is expressed thanks to the ETAs. Here are typical variabilities:

- Additive : ``CL  = TVCL + EXP(ETA(1))``
- Proportional : ``CL  = TVCL * (1 + EXP(ETA(1))``
- Exponential : ``CL  = TVCL * EXP(ETA(1))``

Then THETA are typically the ones found the the population PK papers. The order is important, as the indices will follow it. For instance, here, THETA(1) is for CL, THETA(2) for V, and so on.

::

    $THETA
    14.3 FIX ; CL
    347 FIX; V
    0.609 FIX; Ka
    1; F
    5.42 FIX
    1.49 FIX
    -5.81 FIX
    -0.806 FIX
    70 FIX
    50 FIX
    46.2 FIX

The error model is then described. Here, for a posteriori predicition, and an exponential residual error, the error description is a bit tricky. This is explained in the corresponding a posteriori subsection.

::

    IPRE = -5 ; arbitrary value; to prevent from run stop due to log domain error
    IF (F.GT.0) IPRE = LOG(F) ; note: in FORTRAN, LOG() means natural logarithm, not decimal!
    Y = IPRE + EPS(1)
    IPRED=F

Then, we write a description of the OMEGA matrix. It can be a variance-covariance matrix or a standard deviation-correlation matrix. We suggest to use the latter, as the Tucuxi drug files use standard deviation and correlations.

::

    $OMEGA STANDARD CORRELATION BLOCK(2) FIX
    0.356; IIV CL
    0.798 0.629; IIV V

The Sigma vector, used for the residual error model, is then written.

::

    $SIGMA 0.3138 STANDARD FIX

We inform NONMEM about the calculation to be done. Here we want an aposteriori estimation of parameters:

::


    $EST METHOD=1 INTER MAXEVAL=0 NOABORT NSIG=3 PRINT=1 POSTHOC


And finally we let NONMEM know in what file the result shall be saved, and what is the format of this file. Here we see that the file will have no header, and at least columns for ID, TIME, AMT, DV, and Y:

::

    $TABLE UNCONDITIONAL ID EVID TIME DV IPRED Y NOPRINT ONEHEADER FILE=aposteriori.out.dat


All four computations have some common fields, that are : $SUB, $PK and $THETA. Therefore, they will be written in a single file, and included within the specific files thanks to the $INCLUDE command.

The file containing $PK and $THETA shall be named <druggmodelid>.pkmodel

For instance, here is the file ch.tucuxi.imatinib.gotta2012.pkmodel:

.. literalinclude:: ../../../data/nonmem_models/ch.tucuxi.imatinib.gotta2012.pkmodel

All files will also start with an include of an header. This header will simply set some buffer sizes, to avoid unsuccessful computations.

Therefore, every NONMEM drug specific file shall start with:

::

    $INCLUDE general.header

The listing of general.header:

.. literalinclude:: ../../../data/nonmem_models/general.header

Another standard include will be the file containing data. It will be done with the following line:

::

    $INCLUDE general.dataimport

Finally, there will be a specific include at the end of each drug specific file. This include will depend on the type of computation, and will be presented in the corresponding subsections.

So, now that we have the general structure, let's have a look at the 4 variations. Let's start with a priori predictions.


-------------------
A priori prediction
-------------------

Here is the listing of ch.tucuxi.imatinib.gotta2012.apriori:

.. literalinclude:: ../../../data/nonmem_models/ch.tucuxi.imatinib.gotta2012.apriori

The $INPUT line shall contain at least :: ``$INPUT ID TIME EVID AMT CMT SS II DV``. Then it is followed by the covariates. Be careful, the order has to be the same as the one found in the Tucuxi drug file.

The error model shows no error, as we are only generating a single a priori prediction. It implies that ``Y=F``.

Omega has to be set to 0 as well as Sigma, for the same reason.

All a priori files should look quite identical. The $ERROR should be totally identical, while $OMEGA and $SIGMA sizes have to correspond to the number of Etas, respectively of Eps.


--------------------
A priori percentiles
--------------------


Here is the listing of ch.tucuxi.imatinib.gotta2012.apriori.perc:

.. literalinclude:: ../../../data/nonmem_models/ch.tucuxi.imatinib.gotta2012.apriori.perc


The $INPUT line shall contain at least ``$INPUT ID TIME EVID AMT CMT SS II DV``. Then it is followed by the covariates. Be careful, the order has to be the same as the one found in the Tucuxi drug file.

The file is used to generate random patients, therefore the inter- and intra-individual variability is of primary importance.

The $ERROR shall contain the residual error model. Be careful, here we replace the EPS() by ETA(), so has to be able to generate random values.

$OMEGA is the Omega matrix, and can be written in terms of standard deviation and correlation instead of variance-covariance matrix. As the Tucuxi drug file uses standard deviation and correlation, it is strongly suggested to do the same for Omega.

Initially Omega is meant to embed the inter-individual variability. However, for a priori percentiles we add one or more fields to it for the intra-individual variability. They will be used by the error model. For instance, here, the error model is ``Y= F * EXP( 0.318 * ETA(3))``, so we add ``$OMEGA 1 FIX`` to let NONMEM generate a random intra-individual variability.

$SIGMA is simply 0, and not used at all for the precentiles, replaced by the omegas.

-----------------------
A posteriori prediction
-----------------------

Here is the listing of ch.tucuxi.imatinib.gotta2012.aposteriori:

.. literalinclude:: ../../../data/nonmem_models/ch.tucuxi.imatinib.gotta2012.aposteriori


The $INPUT line shall contain at least ``$INPUT ID TIME EVID AMT CMT SS II DV MDV``. Then it is followed by the covariates. Be careful, the order has to be the same as the one found in the Tucuxi drug file. As you may notice there is a small variation compared to a priori: the MDV field. It is used to get data for all required times.


The $ERROR shall contain the residual error model.

Here are potential error models:

- Additive : ``Y = F + ETA(1)``
- Proportional : ``Y = F * (1+ ETA(1))`` This still has to be validated
- Exponential :

::

    IPRE = -5 ; arbitrary value; to prevent from run stop due to log domain error
    IF (F.GT.0) IPRE = LOG(F)
    Y = IPRE + EPS(1)

For the exponential, the trick is to use a data file with log concentrations instead of concentrations, and use the above error model.

$OMEGA is the Omega matrix, and can be written in terms of standard deviation and correlation instead of variance-covariance matrix. As the Tucuxi drug file uses standard deviation and correlation, it is strongly suggested to do the same for Omega.

Finally, $SIGMA can have one or more values corresponding to the residual error model, so there is one sigma per eps.
